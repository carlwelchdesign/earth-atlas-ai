## Operating agreement

- The local backlog defines intended scope and acceptance criteria.
- Asana records execution state, ownership, blockers, discussion, and verification evidence.
- At ticket start, add a comment with branch, scope, and planned validation.
- During work, comment only for material progress, decisions, changed risk, or blockers; do not generate activity noise for automatic field changes.
- At completion, add a concise evidence comment with commit/PR, tests/build, runtime or visual evidence, artifacts, and remaining risk, then mark complete.
- If acceptance changes, update the local backlog/decision log and the Asana task in the same delivery ticket.
- Never mark a local prototype as production-ready; provider activation, deployment, operations, security/privacy review, and public release stay distinct.
